# Ручний QA пакета XML і відкриті питання

ТЗ: `docs/specs/2026-11-dps-xml-package.md`. Автоматичні перевірки (`npm test`, CI `test.yml`)
валідують кожен згенерований файл офіційними XSD; цей документ — те, що можна перевірити лише
вручну в Електронному кабінеті.

## Імпорт еталонного пакета (без надсилання)

Е-кабінет приймає документ лише з РНОКПП власника КЕП, тому дані платника — ваші власні.

1. `npm start`, відкрити форму, рік **2025**.
2. Ввести свої ПІБ, РНОКПП, код і назву ДПІ, податкову адресу.
3. Додати позиції еталону (валюта USD, курси підтягнуться з НБУ — суми відрізнятимуться від
   еталону з умовними курсами, це нормально):
   - AAPL: купівля 10.01.2025 $1500, продаж 20.06.2025 $2000, витрати — комісії $1 + $1 у грн;
   - MSFT: купівля 03.02.2025 $2100, продаж 15.09.2025 $1900, витрати — комісії $1 + $1 у грн;
   - дивіденд AAPL 15.03.2025 $100.
4. «Збиток минулих років» = 3000.
5. «Завантажити пакет для Е-кабінету» → два файли `…F0100215…xml` і `…F0121215…xml`.
6. cabinet.tax.gov.ua → «Введення звітності» → «F01 Прибуток» → 2025 → завантажити з XML обидва файли.
7. Перевірити, що Ф1 показано як додаток декларації; «Перевірка документа» без помилок.
8. **Зберегти чернетку і видалити її. Не підписувати і не надсилати.**
9. Скріншоти кроків 6–7 додати до статті `src/content/articles/uk-ua-submit-dps-package.md`
   і зафіксувати точні назви кнопок.

Повторити для «Уточнююча» (номер документа 1, будь-який реєстраційний номер) і для пакета лише з
дивідендом (один файл без `LINKED_DOCS`).

Окремо (відкрите питання 8): вивантажити XML будь-якої чернетки F0100215 із самого кабінету й
подивитися, чи є переноси рядків між елементами. Якщо є — `ELEMENT_SEPARATOR` у
`src/app/lib/dps-xml/xml.ts` можна змінити на `'\r\n'`.

## Відкриті питання: реалізовані значення за замовчуванням

| # | Питання | За замовчуванням | Де змінити |
|---|---|---|---|
| 1 | Дата курсу доходу від продажу | дата угоди; дата розрахунку IB зберігається в `saleSettlementDate` | `position-rates.ts` |
| 2 | Курс для витрат | курс НБУ на дату кожної витрати, у її валюті | `position-rates.ts` |
| 3 | Поріг 170.2.8 «а» — місяць чи рік | річна сума доходу від продажу (гр. 4 рядка 1) | `INVESTMENT_THRESHOLD`, `versions.ts` |
| 4 | Код 2 чи 4 через іноземного брокера | 4, з ручним перевизначенням у кожному рядку | `f1AssetCode`, `f1.ts` |
| 5 | Віртуальні активи в Ф1 | не включаються, попередження | `computeF1`, `f1.ts` |
| 6 | Опціони й деривативи | розрахунок без змін, попередження | `computeF1`, `f1.ts` |
| 7 | Версія форми для кампанії 2027 | F0100215 / F0121215 для 2026; перевірити реєстр у грудні 2026 – січні 2027 | `FORM_VERSIONS`, `versions.ts` |
| 8 | Переноси між елементами | без пробільних символів | `ELEMENT_SEPARATOR`, `xml.ts` |
| 9 | Метод визначення лотів | IB — лоти брокера, Freedom — FIFO; метод виводиться в PDF/Excel | `calculationNotes`, `tax-model.ts` |

Також на перевірку:

- Поріг 2026 року — 4 660 грн (1,4 × 3 328): звірити з прожитковим мінімумом на 01.01.2026.
- Пороги 2019–2024 у `INVESTMENT_THRESHOLD` розраховано за прожитковими мінімумами на 1 січня
  відповідних років.
- Для 2024 року версія 14 (`FORM_VERSIONS`) — звірити з архівом реєстру е-форм.
- IB Closed Lots без розділу Execution: виручка лишається нетто (з попередженням при імпорті).
